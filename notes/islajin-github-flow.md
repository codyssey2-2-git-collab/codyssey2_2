# GitHub Flow 학습 노트

## GitHub Flow란?

`main`을 팀 기준에서 정상 동작하는 상태로 유지하고, 각 작업을 별도의 `feature/*` 브랜치에서 진행하는 협업 방식이다. 작업이 끝나면 PR을 열어 리뷰를 받고 `main`에 병합한다. 이 저장소에서는 `main`에 직접 push하지 않고 PR을 통해서만 변경한다.

## 브랜치를 나누는 이유

Git 브랜치는 파일의 복사본이 아니라 특정 커밋을 가리키는 이름이다. 작업마다 브랜치를 나누면 서로의 변경 사항을 바로 섞지 않고 독립적으로 작업할 수 있다. 리뷰를 마친 변경만 `main`에 반영하므로 안정적인 상태를 유지하기 쉽다.

## 작업 흐름

1. **Issue 생성:** 할 일과 작업 목적을 기록한다.
2. **feature 브랜치 생성:** `main`에서 작업용 브랜치를 만든다.
3. **변경 및 커밋:** 변경 대상을 알 수 있는 메시지로 작업을 기록한다.
4. **PR 생성:** 본문에 `Closes #이슈번호`와 변경 사항(What), 변경 이유(Why), 검증 방법(How)을 적는다.
5. **리뷰 및 병합:** 팀원의 의견을 반영하고 최소 1명의 승인을 받은 뒤 `main`에 병합한다.
6. **다음 작업 시작:** 병합 후 `main`으로 이동해 최신 변경을 받아온 다음, 새 `feature/*` 브랜치를 만들어 다음 작업을 시작한다.

## 배운 점

Issue에는 **왜 작업을 시작했는지**, 커밋에는 **무엇을 변경했는지**, PR에는 **어떻게 검증하고 합의했는지**가 남는다. 이 기록을 연결하면 팀원이 변경 이유를 다시 찾기 쉽고, 검토가 끝난 작업만 `main`에 모을 수 있다.
